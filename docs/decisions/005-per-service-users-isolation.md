# ADR 005: Per-Service OS Users with Rootless Podman

**Status**: Accepted · **Date**: 2026-08-09

## Context

One Hetzner box (`llunde-01`, 2 vCPU/4 GB) carries multiple trust domains: the llunde backend (with Postgres and Valkey), the llunde frontend, public ingress — and historically unrelated projects too (openclaw lived here; more may come). A single deploy user with podman-network segmentation was considered; the owner chose the stronger boundary **because** unrelated workloads share the machine.

## Decision

Every service runs under its **own OS user** with rootless podman, quadlets system-placed per-user ([ADR 004](004-quadlet-own-abstraction.md)):

| User | Runs | Publishes |
|---|---|---|
| `llunde-backend` | backend + Postgres + Valkey on a private per-user podman network | API only, `127.0.0.1:8080` |
| `llunde-frontend` | static-server container | `127.0.0.1:8081` |
| `edge` | Caddy ([ADR 006](006-caddy-ingress.md)) | `80`/`443` public — the only public ports |
| *(reserved)* `openclaw` | nothing (not redeployed by this repo, [ADR 001](001-nixos-declarative-host.md)) | — |

- **The load-bearing fact**: rootless podman networks cannot span users. Cross-service traffic therefore travels **loopback-only** — Caddy proxies to `127.0.0.1:<port>`; services never see each other except through published loopback ports. The frontend cannot reach Postgres *by OS boundary*, not by configuration discipline.
- `edge` binds 80/443 rootlessly via `net.ipv4.ip_unprivileged_port_start = 80` (declared in the profile).
- Inside `llunde-backend`'s user, only the API port leaves the private network; Postgres and Valkey are unreachable from outside that user entirely.
- **Resource caps are declared in the units** so the shared 4 GB box stays honest: JVM `-Xmx` for the backend, `shared_buffers` for Postgres, `maxmemory` for Valkey (argon2id's 19 MiB × parallelism is part of the backend budget). Rescaling the box later is additive — the caps just get raised.

## Alternatives considered

- **One deploy user + podman network segmentation** — good blast-radius for network access, but a container escape or user-level compromise reaches every service's files and processes. Insufficient for a box hosting unrelated projects.
- **Per-service VMs / separate boxes** — the real answer at scale; not at this budget.
- **Root podman with userns isolation only** — weaker than distinct users and conflicts with [ADR 004](004-quadlet-own-abstraction.md)'s rootless model.

## Consequences

- Operating a service means `sudo -iu llunde-backend systemctl --user …` (or `machinectl shell`); the runbook documents the idiom once.
- Every service addition costs a user + subuid range + linger, all generated by mkQuadlet — ceremony paid in declarative code, not manual steps.
- Loopback port numbers become a small shared registry (documented in `modules/users/`), since collisions would be silent.

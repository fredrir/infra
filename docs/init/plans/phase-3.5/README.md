# Phase 3.5 — the final push to full NixOS (full plan)

`llunde-parser` is the last imperative machine. This phase wipes and reinstalls it as NixOS via the same nixos-anywhere path that built `llunde-01`, carrying **two live productions** across: pyparser (today: rootful docker-compose under `leploy`) and portfolio (today: self-managed rootless podman quadlets under `portfolio`). The phase-3 gate closed 2026-08-09 with everything that de-risks this one done: states in one flat S3 root, CI restored, tailnet-only management, zone in tofu.

The governing principle, owner-stated: **little to no difference between the boxes and services — NixOS on both, shared abstractions, configs, tunnels, and CI; only service-specific configuration differs** ([ADR 016](../../../decisions/016-tenant-slots-host-uniformity.md)).

**Reads first**: [phase-3-mapping](../../../research/phase-3-mapping.md), [docs/pyparser/PROD.md](../../../pyparser/PROD.md), ADRs 015/016, [contract.md](contract.md). Ground truth recon (2026-08-09, on-box): **UEFI** boot (same systemd-boot disko as llunde-01), single disk `/dev/sda` 152.6G (63G free), pyparser data is small (pgdata 98M, files volume 308M, local backups 27M), portfolio's podman volumes are ~40M each, postgres 17 on both stacks, portfolio's actual subuid range is `100000:65536` (its bootstrap script's 200000 claim is stale — reality wins).

## Decisions (settled here; owner veto at plan review)

1. **Hostname stays `llunde-parser`.** The tailnet name is baked into working CI secrets (`PYPARSER_HETZNER_HOST`, portfolio's `DEPLOY_HOST`) and both survive the reinstall untouched **only if the name is actually reclaimable**: the old (non-ephemeral) node record keeps the MagicDNS name after the wipe, so it must be deleted in the admin console *before* the new install's `tailscale up` — otherwise the new box becomes `llunde-parser-1` and every consumer resolves a corpse. Known_hosts entries change regardless (new host key) — including portfolio's `DEPLOY_KNOWN_HOSTS`, which lives at the **Production environment** level (the phase-3 shadowing lesson).
2. **pyparser converges on pull-based deploys with zero image changes.** A oneshot `pyparser-migrate` quadlet runs `alembic upgrade head` from the *same* `pyparser-review` image (command override); app units order `After=`/`Requires=` it. `podman-auto-update` polls `:latest` exactly like llunde-backend; alembic is idempotent on restart. Worker drain semantics carry over as `TimeoutStopSec` (90s/45s, still > the in-app drain timeout). Rollback = pin `Image=` to a digest, deploy (runbook §9 pattern). The interim CI-SSH deploy workflow is cut down to build+prune only — ADR 015's scaffolding clause fulfilled; the Doppler `pyparser/ci` SSH key/host/Tailscale secrets retire.
3. **Dozzle and socket-proxy are dropped, not ported.** Quadlet containers log to journald; `journalctl` over the tailnet replaces the `/logs` browser view until phase 4's observability collection builds something better. This retires `parser.llunde.no/logs` — an owner-visible feature removal, flagged deliberately. (It also deletes the stack's only docker-socket exposure.)
4. **pyparser backups fold into `modules/backups/`** (restic + pg_dump preHook + the files volume, weekly like llunde-backend — ADR 011): the `db-backup`/`backup-ship` sleep-loop containers retire. The existing `s3://…/pg-backups/` prefix stays as a frozen archive; PROD.md's restore section is rewritten for restic.
5. **Secrets model mirrors llunde-01**: **four** sops-nix bootstrap secrets (fresh Doppler `pyparser/prd` host token, tailscale auth key, restic password+env, ghcr auth for the private `pyparser-review` package); everything else — `POSTGRES_PASSWORD` included, single-sourced — arrives via a host-side render of Doppler `pyparser/prd` into one root-owned `EnvironmentFile` that **every** stack unit consumes, exactly as compose's `env_file` does today. The pyparser image stays untouched, no doppler CLI baked in; the render must be explicitly ordered before the user manager starts (user units can't `After=` system units — the mechanism is stream B's deliverable and the reboot test's proof). Becoming two-host also means real `.sops.yaml` work: per-host creation rules, `sops updatekeys` re-encryption of shared files, and `modules/secrets` parameterized per host. `TUNNEL_TOKEN` stays in Doppler `pyparser/prd` (exact key name verified against the live config before freeze — it appears in no repo) and reaches cloudflared via that env file; **the tunnel is never rotated**.
6. **The portfolio tenant slot** (`modules/tenants/`, ADR 016) declares: user `portfolio`, uid 3000, subuid/subgid `100000:65536` (current reality), linger, and its documented host deps (cosign, doppler, python3, rsync). Everything in `$HOME` stays portfolio's own; its `install.sh`/restore/deploy run per **its** runbooks against the slot. Its Ubuntu-only `bootstrap.sh` is simply never run on NixOS.
7. **Rehearsal before wipe, on a disposable Hetzner server** (hourly-billed): install the same host config, restore pyparser from fresh dumps, prove the stack healthy in-box — with **cloudflared masked** (a second live connector would receive real production traffic) and **without the production tailnet identity** (tailscale disabled or hostname overridden; the scratch box must never join as `llunde-parser` while prod lives). This requires the llunde-parser host identity to be **pre-generated in step 0**, not at cutover — the rehearsal box decrypts with the same key the real install later receives. Portfolio's data-restore is already proven weekly by its own `restore-test.timer`; the rehearsal proves the *slot* (user, subuids, quadlet generation) instead.

## Hard rules

1. No reinstall before the rehearsal passes end-to-end and same-day backups of both tenants are verified restorable.
2. Tunnel tokens and Doppler tokens survive the wipe; neither tunnel is regenerated. cloudflared units stay masked on any rehearsal machine, always.
3. Both tenants share the wipe's downtime; restores are **sequential** (pyparser, then portfolio) so failures are attributable. `parser.llunde.no` + `external.llunde.no` + `hansteen.dev` are the gate metrics; accepted downtime is the announced maintenance window only.
4. Runbook discipline as ever: executed literally, deviations fix the doc on the spot.

## Out of scope

Orange-cloud / tunnel-vs-proxy (phase 4 opens with it). Observability collection (phase 4). pyparser repo hygiene (stale monorepo pointers, committed dumps — owner-acknowledged). Any pyparser application-code change.

## Exit criteria (gate)

1. Rehearsal record: scratch box served the full pyparser stack from a restore; slot provisioning proven on it.
2. Both sites serving from NixOS `llunde-parser`; the runbook (extended to two hosts) executed literally at cutover.
3. Pull-based deploy proven: a pyparser push-to-main swaps the digest on the box with **zero SSH** (auto-update), migrate unit runs first; digest-pin rollback exercised once.
4. portfolio redeployed itself onto the declared slot with zero llunde-infra involvement beyond the slot; its synthetic checks and weekly restore-test green post-migration.
5. Backups: restic snapshots for pyparser (db + files) exist in S3 **and** one restore is performed; portfolio's own backup chain verified running.
6. Reboot test: full box reboot → both tenants return unattended. Zero public inbound ports (`ss` + Hetzner firewall both show none).
7. `nix flake check` golden units cover the pyparser stack; tofu plan stays "No changes." throughout (the wipe is invisible to the cloud API).
8. Old world fully retired: docker/leploy gone by construction, CI-SSH deploy path deleted, retired Doppler `ci` secrets removed. Owner review → gate closed; **the estate is 100% NixOS**.
